使用 AI Agent 轻松创建个人博客：从生成代码到上线发布

2026-06-02 · 10 分钟阅读
博客 搭建 教程

一、这篇教程能帮你完成什么？

传统搭建博客通常需要自己了解前端框架、主题配置、Git 命令、服务器部署、域名解析等内容。
现在借助 AI Agent，可以把很多重复性工作交给 AI 处理。你只需要把需求说清楚，并根据提示完成账号授权、仓库创建、域名绑定等关键步骤，就可以比较轻松地搭建一个个人博客。

简单来说，整个流程可以分为四步：

  1. 用 AI Agent 生成博客项目；
  2. 把博客内容改成自己的信息；
  3. 将代码推送到代码托管平台；
  4. 使用 Pages 类静态托管服务部署上线。

二、需要准备哪些工具？

1. AI Agent 工具

可以使用类似 WorkBuddy、Codex 等 AI Agent 工具。
这类工具的作用不是简单聊天，而是可以帮你执行一些开发任务，例如：

  • 下载或初始化博客项目；
  • 修改网站标题、页面文案、菜单和主题；
  • 生成文章文件；
  • 执行 Git 提交和推送；
  • 根据报错日志分析问题并尝试修复。

2. 代码托管平台

建议提前准备一个代码仓库，用来保存博客项目代码。常见选择包括：

  • Gitee；
  • GitHub；
  • GitLab；
  • 其他支持 Git 的代码托管平台。

如果主要面向国内访问，可以优先考虑 Gitee 或国内云服务商支持的代码源；如果使用海外生态，可以选择 GitHub。

3. 静态网站托管平台

博客如果是静态网站，一般不需要单独购买服务器。可以使用 Pages 类平台进行部署，例如：

  • 腾讯云 Pages / EdgeOne Pages；
  • Cloudflare Pages；
  • GitHub Pages；
  • Vercel；
  • Netlify；
  • 其他静态网站托管服务。

需要注意的是，不同平台支持的代码源、免费额度、构建方式和绑定域名规则可能会变化，实际操作时应以平台控制台的当前说明为准。

4. 域名

如果只是测试，可以先用平台提供的默认访问地址。
如果想让博客看起来更正式，可以绑定自己的域名，例如：

blog.example.com
www.example.com

绑定域名时，通常需要在域名解析平台添加 CNAME 或 A 记录，具体按照托管平台提示操作即可。

三、整体搭建流程

第一步：让 AI Agent 初始化博客项目

可以先对 AI Agent 发送这样的提示词：

我准备搭建一个可以部署到静态网站托管平台的个人博客网站。
请你帮我选择一个适合新手维护的静态博客方案，并初始化项目代码。
要求：页面简洁、加载速度快、支持 Markdown 写文章、后续方便修改标题和菜单。

AI 可能会询问你想使用什么框架或主题。
如果你没有特殊要求，可以选择比较常见的静态博客方案，例如 Hugo、Hexo、VitePress、Astro 等。

对于新手来说，选择标准可以简单一点：

  • 想要传统博客风格：可以选 Hugo 或 Hexo；
  • 想要文档风格：可以选 VitePress；
  • 想要更现代的前端体验：可以选 Astro。

不需要一开始就追求复杂功能，先让网站能正常运行、能写文章、能发布，才是最重要的。

第二步：让 AI 修改网站内容

项目生成后，可以继续让 AI Agent 修改网站内容。比如：

请把网站标题改成“Deny 的博客”，副标题改成“记录技术、生活与折腾过程”。
请把首页介绍写得自然一点，不要太像模板。
请把导航栏改成：首页、文章、归档、关于。

如果看到页面上还有默认文字，可以继续告诉 AI：

把页面中的“XX”改成“XX”。
把关于页面改成我的个人介绍，风格自然一点，不要太正式。

建议一次只提一类修改需求，这样 AI 更不容易改错。
例如先改标题，再改导航，再改首页内容，最后再处理主题颜色和文章页面。

第三步：创建代码仓库

在 Gitee、GitHub 或其他代码托管平台中，新建一个仓库。
仓库名称可以简单一点，例如：

my-blog
deny-blog
personal-blog

创建仓库后，复制仓库地址。一般会有两种地址：

HTTPS 地址
SSH 地址

如果你不熟悉 SSH，可以先使用 HTTPS。
如果使用 SSH，需要提前配置 SSH 公钥。

第四步：让 AI Agent 推送代码

仓库创建好后，把仓库地址发给 AI Agent，例如：

我已经创建好了代码仓库，仓库地址是：xxx。
请你把当前博客项目提交并推送到这个仓库。

如果推送失败，常见原因通常有：

  • 没有配置 Git 用户名和邮箱；
  • 没有添加 SSH 公钥；
  • 仓库地址填写错误；
  • 当前目录不是 Git 项目；
  • 分支名称不一致，例如 main 和 master 不一致；
  • 平台需要账号授权或登录验证。

如果 AI 提示需要 SSH 公钥，可以让它生成或查看当前公钥，然后把公钥复制到代码托管平台的 SSH 公钥设置页面。

常见提示词如下：

推送失败了，请你根据报错信息判断原因，并告诉我应该怎么处理。
如果需要配置 SSH 公钥，请一步一步指导我。

添加公钥后，再告诉 AI：

我已经添加好了 SSH 公钥，请继续推送代码。

正常情况下，代码就可以推送到仓库中了。

四、使用 Pages 平台部署博客

代码推送完成后，就可以进入静态网站托管平台进行部署。

一般流程如下：

  1. 登录 Pages 类平台；
  2. 选择“新建项目”或“导入 Git 仓库”；
  3. 绑定代码托管账号；
  4. 选择刚才创建的博客仓库；
  5. 设置构建命令和输出目录；
  6. 启动部署；
  7. 部署成功后访问平台提供的网址。

不同博客框架的构建命令和输出目录可能不同，常见情况如下：

博客框架 常见构建命令 常见输出目录
Hugo hugo public
Hexo hexo generate 或 npx hexo generate public
VitePress npm run docs:build .vitepress/dist
Astro npm run build dist
Vite 项目 npm run build dist

如果不确定怎么填，可以直接把平台要求填写的页面截图或构建日志发给 AI，让它根据项目文件判断。

提示词示例：

这是 Pages 平台让我填写的构建配置。
请你根据当前项目判断构建命令和输出目录应该怎么填。

五、绑定自己的域名

部署成功后，平台通常会提供一个默认访问地址。
如果想使用自己的域名，可以在 Pages 平台中找到“自定义域名”或“绑定域名”功能。

常见步骤如下：

  1. 在 Pages 平台添加自定义域名；
  2. 根据平台提示获取 CNAME 或 A 记录；
  3. 打开域名 DNS 解析管理页面；
  4. 添加对应解析记录；
  5. 等待 DNS 生效；
  6. 回到 Pages 平台完成验证。

例如你想使用：

blog.example.com

通常需要添加类似这样的解析：

记录类型：CNAME
主机记录：blog
记录值：平台提供的目标地址

DNS 生效可能需要几分钟到几十分钟。
如果刚绑定后打不开，不一定是配置错了，可以稍等一会儿再试。

六、如何写文章？

大多数静态博客都使用 Markdown 写文章。
Markdown 的优点是语法简单，适合长期维护。

一篇最基础的 Markdown 文章大概长这样：

---
title: 我的第一篇博客
date: 2026-06-02
tags:
  - 博客
  - AI
---

# 我的第一篇博客

这是我的第一篇博客文章。

## 为什么要搭建博客？

我希望有一个属于自己的空间，用来记录技术学习、项目实践和生活思考。

## 后续计划

以后我会继续更新博客内容，并逐步完善网站功能。

你可以使用 Typora、VS Code、Obsidian 等工具编辑 .md 文件。
如果不会写，也可以直接让 AI 帮你生成文章初稿，再根据自己的经历进行修改。

提示词示例：

请帮我写一篇 Markdown 格式的博客文章，主题是“使用 AI Agent 搭建个人博客”。
要求语言通俗，结构清晰，适合新手阅读。

写好文章后，可以把文章文件交给 AI Agent，让它帮你放到正确目录，并提交发布。

七、进一步简化：做一个可视化文章管理面板

如果你不想每次都手动创建 Markdown 文件，也可以让 AI Agent 帮你做一个简单的文章管理面板。

可以这样提示：

请帮我做一个本地可视化文章管理面板。
要求像发 QQ 空间一样简单，可以新增文章、编辑文章、填写标题和标签，保存后自动生成 Markdown 文件。

进一步还可以让 AI 做一个启动器：

请帮我做一个启动器。
我双击启动器后，可以自动打开文章管理页面，并启动本地预览服务。

这样以后写文章时，只需要双击启动器，进入管理页面，填写标题和正文，再点击保存即可。

不过需要注意：
这种管理面板本质上还是在本地生成文章文件，最后仍然需要提交代码并触发部署。
如果想做到完全自动发布，还需要让 AI 帮你接入 Git 提交、推送和平台部署流程。

八、常见问题与解决方法

1. 推送到仓库失败怎么办？

先看报错信息。常见原因包括：

  • SSH 公钥没有添加；
  • 仓库地址写错；
  • 当前分支和远程分支不一致；
  • 没有 Git 权限；
  • 网络连接异常。

可以把完整报错发给 AI：

这是 Git 推送失败的日志，请你分析原因，并给出具体修复步骤。

2. Pages 构建失败怎么办？

构建失败通常不是网站彻底坏了，而是构建配置、依赖安装或输出目录有问题。

常见原因包括：

  • 构建命令写错；
  • 输出目录写错；
  • Node.js 版本不兼容；
  • 依赖没有正确安装；
  • 项目缺少配置文件；
  • 某些主题或插件报错。

处理方法很简单：
把构建日志复制给 AI，让它判断错误位置。

提示词示例：

这是 Pages 平台的构建失败日志。
请你分析失败原因，并告诉我应该修改哪个文件、哪一行配置。

3. 域名绑定后打不开怎么办？

可以按下面顺序检查：

  1. DNS 解析是否添加正确；
  2. 主机记录是否写对，例如 blog、www 或 @；
  3. CNAME 记录值是否和平台要求一致；
  4. 是否等待了足够的 DNS 生效时间；
  5. Pages 平台是否已经完成域名验证；
  6. 是否开启了 HTTPS；
  7. 浏览器缓存或本地 DNS 缓存是否影响访问。

如果不确定，可以把域名解析截图和平台提示截图发给 AI，让它帮你逐项排查。

4. 为什么我改了文章，网站没有变化？

常见原因有：

  • 文章没有保存；
  • 没有提交到 Git；
  • 没有推送到远程仓库；
  • Pages 平台还没有重新构建；
  • 构建失败；
  • 浏览器缓存导致旧页面仍然显示。

可以先检查仓库中是否已经有新的文章文件。
如果仓库内容已经更新，再去 Pages 平台查看最新一次部署是否成功。

九、新手建议

如果你是第一次搭建博客，不建议一开始就追求太复杂的功能。
可以先完成以下几个基础目标：

  • 网站能打开；
  • 首页标题是自己的；
  • 能发布第一篇文章；
  • 文章链接正常；
  • 手机和电脑都能正常访问；
  • 域名可以正常绑定；
  • 后续文章可以持续更新。

等这些基础功能稳定后，再考虑增加评论、搜索、访问统计、文章分类、美化主题等功能。

搭建个人博客最重要的不是技术有多复杂，而是能长期坚持记录。
AI Agent 可以帮你降低搭建门槛，但真正让博客有价值的，仍然是你持续输出的内容。

十、总结

使用 AI Agent 搭建个人博客的核心不是“完全不懂技术也能一键成功”，而是把复杂步骤拆成可执行的小任务，让 AI 帮你完成代码生成、内容修改、Git 提交和错误排查。

比较推荐的实践方式是：

  1. 先让 AI 生成一个简单静态博客；
  2. 再修改成自己的标题、导航和页面内容；
  3. 把代码推送到 Gitee、GitHub 等代码仓库；
  4. 使用 Pages 类平台部署上线；
  5. 用 Markdown 持续更新文章；
  6. 遇到报错时，把日志交给 AI 分析。

只要按照这个流程操作，即使没有太多前端基础，也可以逐步搭建出一个属于自己的个人博客。
